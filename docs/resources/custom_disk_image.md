# evroc_custom_disk_image (Resource)

Registers an image object stored in an evroc bucket as a custom disk image. Use `fqid` as the `image` of an `evroc_disk`.

The object itself (qcow2 or raw) is uploaded outside Terraform. Terraform owns the rest of the chain: the bucket, the bucket service account that reads it, the registration, and the disks created from it. Deleting the registration does not delete the object or existing disks.

Set `object_version` to pin the registration to one version of the object. Without it, every new disk uses whatever is at `object_path` at that moment, so the image can change under a stable name.

Source, architecture and default disk size are immutable; changing them replaces the registration. Readiness means the platform accepted the registration, not that the object boots. Boot-test a disk before rolling an image out.

## Example Usage

```terraform
resource "evroc_bucket" "images" {
  name                  = "images"
  object_retention_mode = "Versioned"
}

resource "evroc_bucket_service_account" "image_reader" {
  name    = "image-reader"
  buckets = [evroc_bucket.images.name]
}

# Upload the image first, e.g.
#   aws s3 cp node-v1.qcow2 s3://images/images/node-v1.qcow2
#   aws s3api head-object --bucket images --key images/node-v1.qcow2 --query VersionId
resource "evroc_custom_disk_image" "node" {
  name                   = "node-v1"
  bucket                 = evroc_bucket.images.fqid
  bucket_service_account = evroc_bucket_service_account.image_reader.fqid
  object_path            = "images/node-v1.qcow2"
  object_version         = var.image_object_version
  default_disk_size      = 50 # At least the image's virtual disk size.
  os_name                = "ubuntu"
  os_version             = "24.04"
}

resource "evroc_disk" "boot" {
  name  = "boot"
  zone  = "a"
  size  = evroc_custom_disk_image.node.default_disk_size
  image = evroc_custom_disk_image.node.fqid
}
```

## Schema

### Required

- `bucket` (String) Bucket holding the image object. Accepts the bucket name or its FQID (e.g., evroc_bucket.images.fqid). Must be in the same project and region. Changing this forces a new resource to be created.
- `bucket_service_account` (String) Bucket service account authorized to read the object. Accepts the name or FQID (e.g., evroc_bucket_service_account.reader.fqid). Changing this forces a new resource to be created.
- `default_disk_size` (Number) Default disk size in GB for disks created from this image. Must be at least the image's virtual disk size. Changing this forces a new resource to be created.
- `name` (String) Name of the custom disk image. Must be unique within the project and region. Changing this forces a new resource to be created.
- `object_path` (String) Path of the image object within the bucket (e.g., images/node-v1.qcow2). Changing this forces a new resource to be created.

### Optional

- `architecture` (String) CPU architecture of the image. Changing this forces a new resource to be created.
- `description` (String) Free-form description of the image.
- `image_version` (String) Descriptive version of the image build. Does not pin the object; use object_version for that.
- `object_version` (String) Version ID of the object to register, from a versioned bucket. Without it, new disks use whatever object is at object_path at the time they are created. Changing this forces a new resource to be created.
- `os_name` (String) Operating system name (e.g., ubuntu).
- `os_version` (String) Operating system version (e.g., 24.04).
- `project` (String) Project this resource belongs to. Defaults to the provider project. Changing this forces a new resource to be created.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))
- `user_labels` (Map of String) User-defined labels (key/value pairs) for organizing and selecting resources.

### Read-Only

- `fqid` (String) Fully qualified resource ID (FQID). Pass this to evroc_disk.image.
- `id` (String) The ID of this resource.
- `image_id` (String) Unique identifier (UUID) of the custom disk image.
- `ready` (Boolean) Whether the registration is ready for use. Readiness does not verify that the object is a bootable image.
